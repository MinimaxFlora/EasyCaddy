Install

三分钟，换上一个更完整的 Caddy。

安装脚本会导入签名公钥、写入 APT 源和 pin，并处理与官方同版本包的替换。可重复执行，升级也用它。

curl -fsSL @PAGES_BASE_URL@/install.sh | sudo bash

自动完成：安装依赖 → 导入公钥 → 写 APT 源与 pin → 安装 caddy → 启用并启动 systemd 服务。

包版本与官方一致。脚本使用 --reinstall 和 APT pin，确保选中这个带插件的构建，而不是跳过安装。 
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf '@PAGES_BASE_URL@/public.key' \
  | sudo gpg --dearmor -o /usr/share/keyrings/easycaddy-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/easycaddy-archive-keyring.gpg] @PAGES_BASE_URL@/ ./" \
  | sudo tee /etc/apt/sources.list.d/easycaddy.list
printf 'Package: caddy\nPin: origin "caddy.tatalvpai.vip"\nPin-Priority: 1001\n' \
  | sudo tee /etc/apt/preferences.d/easycaddy
sudo chmod o+r /usr/share/keyrings/easycaddy-archive-keyring.gpg
sudo chmod o+r /etc/apt/sources.list.d/easycaddy.list
sudo apt update
sudo apt install --reinstall caddy
不要同时启用官方 Caddy APT 源。两者包名和版本相同，apt 只能靠 pin 区分；install.sh 会自动把官方源改名为 .disabled-by-easycaddy。 
sudo apt update
sudo apt install --only-upgrade caddy
apt-cache policy caddy

站点保留最近 3 个版本，旧版本仍可从 GitHub Releases 下载。需要固定版本时，用 apt 显式安装指定版本。

不要运行 caddy upgrade：它会下载官方二进制并覆盖当前文件，新增模块会全部丢失。

FAQ

常见问题。

更多细节见 GitHub 的 README 与 CONTRIBUTING。

为什么包版本和官方完全一样？

为了与上游 tag 一一对应，Release 仍叫 v@VERSION@，包版本也是 @VERSION@。同版本时 apt 不会自动替换，所以安装脚本使用 --reinstall 并写入 APT pin。

需要删除官方 Caddy 源吗？

建议删除或停用。两个源的包名、版本都相同，apt 只能靠 pin 区分。install.sh 会自动把 caddy-stable.list 改名为 .disabled-by-easycaddy，并写入优先级 1001 的 pin。

为什么 armv6 不在 APT 索引里？

上游把 ARMv6 和 ARMv7 的 deb 都标为 Debian 架构 armhf，同包名、同版本、同架构无法共存于一个 Packages 索引。ARMv7 进入 APT，ARMv6 的 deb/tar.gz 放在 GitHub Release。

如何升级或降级？

升级用 sudo apt update && sudo apt install --only-upgrade caddy。站点保留最近 3 个版本，需要旧版时从对应 Release 下载 deb，或用 sudo apt install caddy=<version>。不要运行 caddy upgrade。

插件版本固定吗？

不固定。每次构建解析各插件仓库默认分支的最新版本，与 --with github.com/... 的默认行为一致。需要可复现构建时，在 workflow 的 PLUGINS 中写死 tag 或 commit。

这是 Caddy 官方构建吗？

不是。EasyCaddy 是非官方重新构建，与 Caddy 项目没有隶属关系。标准构建能复现的问题请报告给 caddyserver/caddy。
